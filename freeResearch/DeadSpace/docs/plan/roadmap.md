# 開發路線圖

> 目標：一次做到完整內容的多人連線版（B 模式：主機瀏覽器 Web Worker 當權威 server、WebRTC P2P、零自架 server）。
> 實務上這是多個 session 的工作量：每個里程碑結束都要 commit＋push，並更新 `../../PROGRESS.md`，下一個 session 用同一份 prompt 就能接著做。
> 美術**不是最後才做**：每個里程碑新增的東西都要直接達到 `../art/art-bible.md` 的品質門檻；M10 只做整體打磨。

## 各里程碑驗收標準

### M0 專案骨架
- `game/` 可 `npm ci && npm run dev`、`npm test`、`npm run build`（輸出 `../play/`）。
- ESLint＋Prettier、TS strict、`sim/` 禁止 import DOM／three（lint 規則或 tsconfig project 分離）。
- `PROGRESS.md` 建立。

### M1 連線與大廳
- Playwright：4 個分頁用 `BroadcastChannelTransport` 建房、加入、改名、選色、準備、開始。
- Trystero 真實連線：在兩個獨立的瀏覽器 context 驗證（若雲端容器連不到公共 relay，記錄於 PROGRESS.md 並保留手動驗證步驟）。
- 斷線 90 秒內重連回原席位。
- 測試掛勾 `testHooks`：Playwright 可強制身分、跳過時間、觸發事件。

### M2 世界基礎
- 女帝號完整內部（醫療區、驗血區、販賣區、實驗室、宿舍、控制室、停機坪），由 ASCII 版面建構。
- 右鍵移動、尋路、避讓、門自動開關；LOS 戰爭迷霧；空白鍵回鏡頭；小地圖。
- 視覺：符合美術聖經 §4–§7，截圖自評通過。
- 洩漏測試框架建立並通過。

### M3 戰鬥與道具
- 18 套防護服可購買、穿上後外觀、武器、技能都正確；道具全部可用。
- 販賣機庫存、補貨、開局延遲、可被摧毀與 EMP 停機；死亡掉落物品。
- 炸彈產生瓦礫、清除裝置可移除。

### M4 身分與陣營
- 3–12 人身分分配符合 GDD §4.1；10 職業配備與被動正確。
- 異形：形態切換（匿名）、感染→spawn、蛋（上限 3、被毀曝光）、T1／T2×3／T3×9 全部型態與技能。
- 變種人：三段進化（進化中無敵）、兩路線全部型態（含 Overlord 先做站內版，M6 補太空站形態）。
- 仿生人：保護規則、關機、記憶卡、復活、遙控器、2000 EP 升級。
- EP 公式與原作一致（單元測試）。
- 死亡觀戰、遺言 4 秒、投票模式、踢人、全體／群組／死者頻道。
- 勝負判定與結算畫面。

### M5–M8
- 各自 GDD 對應章節與 `content-catalog.md` 清單全部打勾；每項都有測試或截圖紀錄。

### M9 AI bots 與練習模式
- Bots 能完成基本循環：人類買裝、移動、驗血；異類感染與進化。用於 headless 對局測試與練習模式。

### M10 打磨
- 美術聖經 §15 完整截圖審查，`game/docs/visual-review.md` 無未解項目。
- 全部 UI 文字可切換 zh-TW／en。

### M11 硬化與上線
- 12 人 headless 對局 × 20 個 seed 無崩潰、無洩漏。
- 注入 150 ms 延遲、5% 掉包仍可正常遊玩。
- `play/` 已 build 並 commit；lab 首頁有入口；`README.md` 有「怎麼開房、怎麼加入、連不上怎麼辦」。

## 每個 session 的工作守則

1. 開工先讀 `PROGRESS.md`，從第一個未完成項目接著做。
2. 每完成一個可驗證的小段落就 commit（訊息用繁中＋英文術語）。
3. 每個里程碑結束：跑全部測試、截圖自評、更新 `PROGRESS.md`、build `play/`、commit、push。
4. 遇到需要使用者決定的事（例如要不要買 TURN），記在 `PROGRESS.md` 的「待決定」區，先用合理預設繼續。
