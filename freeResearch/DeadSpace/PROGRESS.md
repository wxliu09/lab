## 已知問題

- 型別檢查要用 `npx tsc -b`（`npm run typecheck`）：根目錄 `tsconfig.json` 是 `files: []` 的 solution，`tsc --noEmit -p .` 什麼都不檢查。
- 屍體在快照裡不帶名字（`makeCorpse`），所以調查筆記無法自動標出「看過屍體」；要做得先決定屍體名字是否該對看得到的人公開（走近屍體懸停目前可以看到名字）。
- 原生 `title` 在對局畫面一律改用遊戲 tooltip（`tooltip.tsx`，依 title 文字比對）；新元件請直接用 `tipProps`。
- 被攻擊警示以「一份快照之間掉血 ≥ max(8, 2.5% 上限)」判斷，持續傷害不觸發；遊戲沒有「減少動態」設定，看作業系統的 `prefers-reduced-motion`。
- 第一次進站、進太空（不預建的裝置）都會等 GPU fence 再切過去：主機不卡，但軟體繪圖（SwiftShader）下「載入中」會比較久（太空約 15 s，原本 3 s 切過去後畫面卡約 12 s）；等待上限 600 幀。真 GPU 應該很短，未實測。
- 化身的顯示用背包：給假 Bob 一件他「真正背包」已有的唯一道具時，道具仍會掉在地上（可藉此分辨，罕見）。寄放中的道具會套用攜帶被動（和真的帶著一致）。
- 身分轉換（`moveInventory`）時新單位背包較小，放不下的背包道具會直接消失（舊行為）；寄放的道具則掉在腳邊，兩者不一致。
- 練習 AI：easy 下人類方勝場 2／20（normal 7／20，主機當異形或變種人）。換站後 20 局模擬船員勝場 10→5，追死亡紀錄看起來是結局分歧而非途中送命，但樣本小。AI 的決策會用到非公開資訊（艙內有沒有人、掃描結果、玩家怪物與野生生物），只影響 AI、不經快照外洩。所有站都停不了時 AI 會留在太空船艙裡。兩名異類同時存在時，AI 的「兩份感染名單交集只剩一人」指認規則可能指錯人。
- 雜物箱位置每局隨機（數量照原作，不逐一照原作座標）；被毀設施的殘骸只在「看得到那一格」時才換上，視野外維持記憶中的樣子。
- 測試環境：2026-11-02 起這個雲端容器在**同一個瀏覽器開多個分頁**時，分頁共用 SwiftShader GPU 行程，第二個分頁卡在初始化（主選單都出不來），所以 `lobby.spec.ts`、`tools.spec.ts` 等多分頁 e2e 在這裡會逾時；舊版本（`5c77478`）一樣失敗，確認是環境問題。對應的邏輯有單元測試涵蓋；單分頁 e2e（ux、guide、audio）與兩個獨立瀏覽器的線上驗證都通過。在有 GPU 的機器上應照常可跑。
- 死因：「看不見的攻擊者」依死者畫面上實際有的東西（上一個 tick 的視野）判斷，這是刻意的（見 death.ts 註解）。
- 太空：七號廢站刻意保留為最暗的站；主選單的行星夜面現在也隱約看得到陸塊（`makePlanet` 的 `nightK` 預設 0.14，想要全黑改 0）。
- 介面：小地圖與圖例共用 `src/ui/minimapColors.ts`；改形狀時要同步 `Guide.tsx` 的 MapLegend 與 `guide.css` 的 `.guide-sw`。
- 音訊：雲端容器只能量測音量、沒辦法實際聽，聽感需要真人試玩確認。
- 通訊病毒事件互換名字與顏色後，畫面上看不出誰是誰，但封包裡的玩家槽位沒有重新編號，改過 client 的人仍能對回原本的人。要完全做到需要每位觀看者各自的槽位映射，暫不處理。
- `src/devtools/modelGallery.ts` 是開發用模型展示頁，不進正式 build。
- 偽裝（千面）時換新 id 能擋住「用 id 連續性分辨真假」，但改過的 client 仍可記住「真本人的 id 最後出現在哪裡」來推斷；要完全防止需要每位觀看者各自的 id 別名表，暫不處理。
- 給別人唯一道具（例如基因檢測器）時，對方已有或背包滿會有不同結果，可以用來探測背包（原作行為，低風險）。
- 小地圖：動力分配台是控制台色的實心小方塊，圖例上容易和窗戶混淆；小地圖點移動已避開控制圈，但直線走過去仍可能踩進圈裡開始駕駛（已讓擦過控制圈的方向扣分）。
- 吞噬提示的 +EP 數字照內容表，沒有乘大廳的 EP 倍率（client 拿不到）；頭上浮出的 +N 是實際增加量。
- 隱形單位仍會讓自動門打開並留下一筆「未知」剪影的門禁紀錄（不暴露是生物或人形，但看得出有東西經過）。
- 死者附身的蛞蝓仔用旁觀者視野判斷可指揮目標，理論上能用蛞蝓的動作向活人傳遞資訊（原作也一樣）。
