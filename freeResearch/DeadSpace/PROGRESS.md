## 獨立洩漏審查（2026-10-30）

由沒看過實作的審查者讀協定與可見性過濾，並寫最小重現。已修正：
- 大廳廣播地圖種子 → 可在本機重算全員身分：種子只留在主機；身分分配與實體 id 改用獨立的密碼學亂數流。
- 聊天泡泡的實體 id 把匿名單位和說話者綁在一起：只附給看得到的人，匿名或被消音時不附。
- `tg`（動作目標）一直保留最後目標：只在攻擊／施法中且目標可見時送出。
- 特效的次要欄位（`e2`、`x2/y2`、偷竊的道具 id）與隱形施放者的座標後備：逐欄過濾。
- 偽裝與分身沿用舊 id：千面、疊影、時滯牢籠改發新 id；快照依隨機 id 排序。
- 門禁紀錄可隔牆讀取：要看得到那扇門。
- `-rename` 可冒用他人名字：禁止重名。
- 冒充主機搶先回應可竊取重連 token：token 與主機 peer id 綁定。
- 道具點目標座標未限制範圍、穩定度可反推末日精確時間：已限制／降解析度並加隨機偏移。

## 真實 WebRTC 驗證

- **容器內已驗證可用**：兩個獨立的 Chromium（不同 browser 實例）透過 Trystero＋公共 Nostr relay 建立 WebRTC，進入同一房間並同步大廳（`tests/e2e/p2p.spec.ts`，需外網：`XC_P2P=1 npx playwright test p2p`；Playwright 要設 proxy bypass `localhost,127.0.0.1`）。
- 多分頁流程測試用 `BroadcastChannelTransport`（`?net=bc`）。
- **手動驗證步驟（朋友之間）**：
  1. 主機開 `play/index.html`（GitHub Pages 網址），輸入名字 → 建立房間，把 5 字元房號傳給朋友。
  2. 朋友開同一網址，輸入名字與房號 → 加入。30 秒內沒進大廳：設定頁把信令改成 MQTT 或 BitTorrent 再試。
  3. 若在對稱 NAT（公司網路、部分手機熱點）連不上：設定頁填入 TURN 伺服器（見「待決定」）。
  4. 主機把分頁切到背景時，其他人會看到「主機在背景」提示；主機分頁不要關。

## 已知問題

- 通訊病毒事件互換名字與顏色後，畫面上看不出誰是誰，但封包裡的玩家槽位沒有重新編號，改過 client 的人仍能對回原本的人。要完全做到需要每位觀看者各自的槽位映射，暫不處理。
- 手榴彈等投射物會穿過關著的門（投射物只把牆當障礙）。
- 千面（假面者）化身後，聊天已改顯示偽裝對象的名字與顏色；但時滯殭屍被喚回後會立刻換成目前的 spawn 型，不會保留殭屍本體。
- 擬人株污染販賣機、GIT 解析器等機制依賴販賣機庫存；開局已初始化，但對局中新生成的販賣機要記得呼叫 `initVendor`。
- `src/devtools/modelGallery.ts` 是開發用模型展示頁，不進正式 build。
- 偽裝（千面）時換新 id 能擋住「用 id 連續性分辨真假」，但改過的 client 仍可記住「真本人的 id 最後出現在哪裡」來推斷；要完全防止需要每位觀看者各自的 id 別名表，暫不處理。
- 給別人唯一道具（例如基因檢測器）時，對方已有或背包滿會有不同結果，可以用來探測背包（原作行為，低風險）。
- 隱形單位仍會讓自動門打開並留下門禁紀錄（物理上合理，但等於暴露有隱形單位經過）。
- 死者附身的蛞蝓仔用旁觀者視野判斷可指揮目標，理論上能用蛞蝓的動作向活人傳遞資訊（原作也一樣）。
- 豪勇號降落時，停在它上面的船仍可發射；翠原星的轟炸系統未實作（原作的「轟炸進度」）。
- CEO 是仿生人時，仿生人重生不會補生成管家。
